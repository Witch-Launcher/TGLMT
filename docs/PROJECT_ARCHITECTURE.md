# TGLMT — Project Architecture

> OpenGL 4.6 **Core Profile** implemented on top of **Apple Metal**, targeting
> iOS on Apple A11 (and later Apple GPUs).

This document describes the architecture as it exists in the tree, with file
and line references. Every number below was measured from the repository, not
estimated.

---

## 1. Scope and non-goals

| In scope | Out of scope |
|---|---|
| OpenGL 4.6 **Core Profile** (657 entry points) | OpenGL compatibility profile (42 extra entry points are implemented and exported, but are **not** core) |
| GLSL 4.60 | GLSL ES 3.x, ESSL 3.2 |
| Desktop GL semantics (fixed-function pipeline is emulated in the shader) | OpenGL ES |
| Apple Metal backend (iOS/macOS) | Vulkan, Direct3D, OpenGL-on-GL |

The project implements the **core profile** only. `glGetString(GL_VERSION)`
reports `4.6 (TGLMT Metal port, build <n>.<hash>)` and
`GL_CONTEXT_PROFILE_MASK` reports `GL_CONTEXT_CORE_PROFILE_BIT` without the
compatibility bit (`src/gl/gl_get.cpp`).

## 3. Layering

```
   Application (LWJGL / Minecraft / AquariumBench)
        │  dlsym("glFoo")
        ▼
┌──────────────────────────────────────────────────────────────────┐
│ src/gl/gl_c_exports.cpp     extern "C" wrappers, 1:1 forward    │
│                             (generated by tools/gen_c_exports.py)│
├──────────────────────────────────────────────────────────────────┤
│ src/gl/gl_*.cpp             OpenGL 4.6 Core implementation        │
│   • validation + GL error generation                           │
│   • object / state management                                  │
│   • translation to the Metal abstraction                        │
├──────────────────────────────────────────────────────────────────┤
│ src/gl/glsl_to_msl.cpp      GLSL 4.60 → MSL translator          │
│   (12 564 LOC, ~60 rewrite passes)                             │
├──────────────────────────────────────────────────────────────────┤
│ include/tglmt/MetalInterface.h  abstract Metal backend (83      │
│                                 virtuals on IDevice)              │
├──────────────────────────────────────────────────────────────────┤
│ src/metal/AppleMetalBridge.mm  real Metal (id<MTL*>, ARC)        │
│ src/metal/NullMetalBackend.cpp CPU shadow backend (for CI)       │
└──────────────────────────────────────────────────────────────────┘
        │  id<MTLCommandEncoder>, id<MTLRenderPipelineState>, …
        ▼
   Metal / GPU
```

### 3.1 Call path in detail

```
glDrawElements(mode, count, type, indices)
  → src/gl/gl_c_exports.cpp:…            extern "C" wrapper (GlProfileScope timer)
  → tglmt::gl::glDrawElements            src/gl/gl_draw.cpp
      → EmitDraw()                        validation (mode/type/count), GL error
      → AppleDrawGL()                     src/gl/gl_apple_draw.cpp
          → Context::state (StateTracker) current GL state
          → PipelineKey lookup / makeCustomPipeline
          → IRenderEncoder::drawIndexedPrimitives
  → AppleMetalBridge.mm                  id<MTLRenderCommandEncoder>
```

The API layer is **not** a function-pointer dispatch table — `src/gl/gl_dispatch_gen.cpp`
is a *name manifest* used by the audit tooling only, and has no runtime consumer.
Every entry point is a direct C++ function, so validation is per-entry-point
(this is the root cause of the error-generation gaps fixed in Phase 5; see
`reports/AUDIT_REPORT.md`).

### 3.2 Two backends, one interface

`include/tglmt/MetalInterface.h` declares an abstract `IDevice` with **83
virtual methods** plus small value types (`PipelineOpts`, `SamplerDesc`,
`CustomAttrib`, `PixelFormat`, …). Two implementations exist:

| Backend | File | Purpose |
|---|---|---|
| Apple | `src/metal/AppleMetalBridge.mm` (3 504 LOC) | Real Metal. Compiled only when `TGLMT_APPLE_METAL=ON`; requires ARC (`-fobjc-arc`). |
| Null | `src/metal/NullMetalBackend.cpp` (79 LOC) | CPU shadow + a draw trace. Used by unit tests and CI without a GPU. |

The null backend is **not** behaviourally equivalent to the Apple backend: it
collapses MRT to one attachment, ignores texture upload payloads, has no mip
chain and dispatches compute with a fixed 8×8 grid. Tests that need real GPU
semantics are therefore in `tests/integration/` and skip on the null backend.
This asymmetry is a known limitation and is documented in
`docs/TESTING_STRATEGY.md`.

## 4. Core data structures

### 4.1 `Context` (`include/tglmt/Context.h`, 1 274 lines)

One GL context. Owns:

* **Object maps** — `buffers`, `vaos`, `textures`, `samplers`, `shaders`,
  `programs`, `pipelines`, `fbos`, `renderbuffers`, `queries`, `syncs`, `xfbs`
  (12 namespaces, matching `ObjectRegistry`'s 12 `ObjectKind`s).
* **State** — a `StateTracker` instance (`include/tglmt/StateTracker.h`).
* **Errors** — an `ErrorTracker` (32-entry FIFO queue, per context).
* **Backend handles** — `device`, pending encoder/target/pipeline, the
  uniform cache, the pipeline MRU cache, the wrap cache, the ring buffer.

Context selection is per-thread via `thread_local Context*`; there is a
process-global fallback context for threads that never called
`Context::MakeCurrent` (`src/core/Context.cpp:114`).

### 4.2 `StateTracker` (`include/tglmt/StateTracker.h`)

Holds the GL state machine: capability enables, blend (×8 draw buffers),
depth, stencil (front/back), viewports (×16), scissors (×16), raster state
(cull/front-face/polygon-mode/offset/line-width/clip-control), pixel-store
state, and all binding points (buffers, textures per target, samplers, VAO,
program, XFB, read/draw FBO).

A generic `SetShadow/GetShadow` byte store backs the state that has no
dedicated field, and is also the mechanism used by `glGet*` for values that
are not modelled explicitly.

### 4.3 `ObjectRegistry` (`include/tglmt/ObjectRegistry.h`)

A single monotonically increasing name space shared by all 12 object kinds
(names are therefore unique across kinds, which is stricter than GL requires
but harmless). `glIsX` returns false for name 0, as the spec requires.

### 4.4 `ErrorTracker` (`include/tglmt/ErrorTracker.h`)

Per-context FIFO of at most 32 `GLenum` errors. `glGetError` pops the front.
`KHR_no_error` support is present but off by default (it is enabled through
the `TGLMT_NO_ERROR` environment variable — TGLMT has no EGL, so there is no
`eglGetError` to piggyback on).

## 5. GLSL → MSL translation

`src/gl/glsl_to_msl.cpp` (12 564 LOC) is a **token/string rewriter**, not a
compiler front end. There is no AST, no type system, no dataflow analysis.
The pipeline is:

```
GLSL source
  → StripComments
  → RenameCxxOnlyKeywords          (MSL is C++14; GLSL identifiers may be C++ keywords)
  → Preprocessor                   (line-oriented; #define/#undef/#if/#ifdef/#else/#endif)
  → Struct split + member table
  → Declaration scan               (uniform / in / out / uniform block / SSBO / image / atomic counter / subroutine)
  → Body rewriting                 (~60 independent passes)
  → MSL emission                   (fixed prelude + stage structs + entry point)
```

Everything it cannot express **fails loudly** (`GLSLConvertResult::ok = false`
plus a human-readable log) rather than emitting a guess. See
`docs/GLSL_460_COMPILER.md` for the supported-feature matrix and the known
divergences.

The GLSL→MSL step happens at `glCompileShader` (`src/gl/gl_shader.cpp:56`);
Metal compilation of the resulting MSL happens at `glLinkProgram`
(`src/gl/gl_program.cpp:1404`).

## 6. Metal backend specifics

* **ARC** (`-fobjc-arc`): every `id<MTL*>` is a strong ivar; there is not a
  single manual `retain`/`release` in the tree. GL-object lifetime maps to
  Metal-resource lifetime through `std::shared_ptr<ITexture>` /
  `std::shared_ptr<IBuffer>`.
* **Pipeline cache**: two layers — a per-context MRU (`Context::pipeCache`,
  8 entries) and a bridge-level map (`AppleMetalBridge.mm` `pcache_`). Both are
  keyed on `ILibrary::identity()` (a per-lifetime serial) **and** on
  `ProgramObject::linkGen` (a per-link counter) — using a raw pointer as the
  program identity is unsafe because `glLinkProgram` frees the old library and
  the allocator frequently hands back the same address.
* **Synchronisation**: there are no `MTLBarrierEncoder`/`MTLAccessor` uses.
  Ordering is achieved by encoder boundaries inside one command buffer, which
  is the correct tier-1 approach for Apple-family GPUs (tier-2 resource
  barriers require Apple9/M1 and are not available on A11).
* **Render passes**: `MTLRenderPassDescriptor` with explicit load/store
  actions; MSAA resolve is done by Metal (`MTLStoreActionMultisampleResolve`).
  Verified against the real Metal compiler: a *hole* in the pipeline's colour
  attachments (`MTLPixelFormatInvalid` for a `GL_NONE` draw buffer) is
  **accepted** by Metal, so no workaround is needed.

## 7. Build system

`CMakeLists.txt` (CMake ≥ 3.20, C++17):

| Option | Default | Effect |
|---|---|---|
| `TGLMT_APPLE_METAL` | OFF | Compiles `AppleMetalBridge.mm`, links Metal/Foundation/QuartzCore |
| `TGLMT_BUILD_TESTS` | ON | Builds all `tests/unit/*.cpp` + `tests/integration/*.cpp` as separate executables registered with CTest |
| `TGLMT_BUILD_SHARED` | ON | Also builds `libtglmt.dylib` for the launcher |
| `TGLMT_FORCE_DIAG` | OFF | Always-on diagnostics |

Notable build decisions:

* `glsl_to_msl.cpp` is compiled at `-O1` (not `-O3`): the file has one
  ~4 200-line function, and LLVM's optimiser is superlinear in function size.
  Measured cost of `-O1` vs `-O3` is +4 % on shader conversion (0.71 → 0.74 ms
  for the heaviest shader), and the build is ~6 s faster.
* All test executables share one precompiled header
  (`<tglmt/gl46.h> <tglmt/Context.h>`) — without it each of the ~185 tests
  re-parses ~4 k lines of headers (~1.2 s/test → ~200 s CPU).
* `glsl_to_msl.cpp` and the Apple bridge are excluded from the *static* and
  *shared* duplication by using an `OBJECT` library.

`make test` builds and runs CTest on macOS; `make ipa` produces the unsigned
iOS IPA.

## 8. Tooling (the "truth" layer)

| Tool | Purpose |
|---|---|
| `tools/gl46_catalog.py` | **Single source of truth** for the OpenGL 4.6 Core catalog (657) and the compatibility-only set (42), derived from `docs/khronos/gl.xml` with Khronos `reg.py` PASS-1 profile semantics |
| `tools/gen_gl_headers.py` | Generates `gl46.h`, `gl46_types.h`, `gl_dispatch_gen.cpp` from `gl.xml` |
| `tools/gen_c_exports.py` | Generates the `extern "C"` wrappers |
| `tools/gen_ext_aliases.py` | Generates extension aliases |
| `tools/gen_stubs.py` | Generates honest stubs for any core entry point not hand-implemented (currently **none**) |
| `tools/gen_state_pnames.py` | Extracts the 341 core state variables from Ch. 23 of `glspec46.core.pdf` and generates `gl46_pnames.h` (the accepted-pname list for `glGet*`) |
| `tools/truth_manifest.py` | Joins registry ⇄ exported symbols ⇄ implementation ⇄ tests into `tests/truth/api_manifest.json` |
| `tools/gen_api_docs.py` | Generates `docs/OPENGL_46_API_INVENTORY.md` + `docs/OPENGL_46_API_COVERAGE.md` from the manifest |
| `tools/scan_behavior_gaps.py` | Heuristic scanner for "skipped / unimplemented" markers in the source |

The design principle: **the registry is the only source of truth for what the
API surface is**, and the manifest is regenerated from it rather than
hand-maintained, so documentation cannot drift away from the implementation.

## 9. Known architectural limitations

| # | Limitation | Impact | Where documented |
|---|---|---|---|
| L1 | The GLSL front end is a rewriter, not a compiler. Unknown identifiers are not diagnosed at compile time (they fail later at Metal compile time). | Shaders with a typo fail at link, not at compile | `docs/GLSL_460_COMPILER.md` |
| L2 | Null and Apple backends are not behaviourally equivalent (MRT, uploads, mips, compute grid). | GPU-only behaviour is untested on CI | `docs/TESTING_STRATEGY.md` |
| L3 | Geometry shaders are rejected (no mesh path on A11). | GL 4.6 core requires GS | `docs/METAL_A11_LIMITATIONS.md` |
| L4 | `glClientWaitSync` does not block (no Metal event). | CPU-side fence waits are not honoured | `docs/METAL_A11_LIMITATIONS.md` |
| L5 | The GL context is not internally synchronised; one context must not be used from two threads. | Requires external locking | `src/core/Context.cpp` |
| L6 | Indirect draws are read back on the CPU instead of executed by the GPU. | A compute shader that generates draw commands is read one frame early | `docs/IMPLEMENTATION_ROADMAP.md` |
